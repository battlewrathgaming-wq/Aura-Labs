# Aura Lab Boundaries

Status: durable boundary record
Date: 2026-06-18

## Core Boundary

Aura Lab owns reusable post-bridge presentation and tooling products.

Source projects own source meaning, adapter behavior, runtime behavior, local adoption, and final product decisions.

```txt
Lab provides the lens or window.
The project owns the view and the meaning.
```

## Lab Owns

Lab owns:

- Lab-local product development
- Lab development shelves and candidate mirrors
- clean consumable product shelves when accepted
- presentation glass and display primitive vocabulary
- Lab-local tooling such as Pane Board
- workflow/lens utilities such as Trace Impression
- Lab documentation around its own products, boundaries, and verification expectations

## Lab Does Not Own

Lab does not own:

- Atlas, Sense, or Core source meaning
- target adapters or mapper constants
- target state enums
- target runtime behavior
- target bridge or IPC contracts
- target schema or persistence decisions
- target adoption timing
- target-local outputs generated after consuming a Lab utility

Shared spelling does not imply shared meaning.

## Presentation Glass Boundary

Presentation glass is a prepared display window.

Lab may provide:

- display primitives
- CSS/token language
- static examples
- presentation heads
- material shelves
- polish and safety floor notes

Target projects provide:

- source meaning
- adapter mapping
- product copy
- runtime behavior
- final composition
- adoption/rejection/adaptation

A project adopting Lab glass does not adopt Lab sample data, example meanings, state labels, tooling, roadmap, or future upgrade path.

## Trace Impression Boundary

Trace Impression is a source-orientation workflow.

Lab may provide:

- the workflow lens
- neutral templates
- command meanings
- quality indicators
- candidate product mirror
- assurance records for the tool itself

The consuming project owns:

- local `context.md`
- local maps and run logs
- local Human orientation frames
- local acceptance, rejection, refresh, or retirement
- all source meaning and follow-up decisions

Trace Impression output is a map, not authority.

It may reveal:

- source-cited facts
- not-proven claims
- open edges
- boundary pressure
- unaccepted shapes

It must not create:

- architecture approval
- Dev authorization
- schema authority
- product doctrine
- accepted terminology

Use `Shape:` for future-facing, projected, inferred, or unaccepted unit labels.

## Pane Board Boundary

Pane Board is Lab-local internal spatial collaboration tooling.

It helps the Human and agents discuss layout intent before product UI is built.

Pane Board outputs are reference material, not product runtime state, component API, CSS spec, bridge contract, or target-project UI.

It is the shadow puppet show: Lab may keep the shadows as reference material, but the board itself does not define the product surface.

## Promotion Boundary

`lab-development/` may contain candidate products, trials, proof notes, and workbench material.

`lab-products/` should contain only clean consumable products.

Development material must not be copied into another project as normal runtime input.

## Authority Reminder

Human owns vision, priority, intended experience, and acceptance.

Lab Overseer owns Lab continuity, milestone meaning, and product-fit review.

Dev implements only a bounded current packet.

Target projects decide whether Lab output is useful locally.
