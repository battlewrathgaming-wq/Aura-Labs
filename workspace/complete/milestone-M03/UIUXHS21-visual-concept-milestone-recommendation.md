## Recommendation

Open the next milestone as a UI/UX visual concept milestone.

Do not open it as:

- a Dev implementation milestone
- a bridge-contract milestone
- an Atlas/Sense/Core adapter milestone
- a stack/framework selection milestone

M01 and M02 proved enough rigging and trust grammar to make the next problem visible: presentation quality. Aura Lab now needs to shape typography, text containment, surface treatment, spacing, and a more beautiful space-game visual language before Dev starts building reusable UI kit pieces.

## Suggested Milestone Focus

Create a visual concept pack for the Aura Presentation Kit.

The pack should include four static concept directions:

- one Aura Lab briefing concept
- one Sense-style tactical HUD concept
- one Atlas-style operator/workbench concept
- one neutral Core seed concept

Each concept should test the same shared presentation grammar:

- shell
- typography
- trust band
- state grammar
- source/freshness language
- panel surfaces
- text containment
- diagnostic demotion

The concepts should differ in information hierarchy and domain posture, not in trust discipline.

## Primary UX Reasoning

Aura Lab has proven that it can present bridge-aware state honestly. The next risk is that honest state can still look cramped, generic, or visually brittle.

The biggest visual failure seen across Atlas/Sense-style surfaces is text behavior:

- wrapping inside narrow panels
- oversized headings competing with operational controls
- sentence copy forced into tiny value cells
- labels and values losing hierarchy
- compact windows turning useful copy into visual noise
- insufficient distinction between primary facts, trust language, and diagnostics

Because of that, the next concept milestone should define text roles and containment rules before sci-fi decoration.

## Typography Before Decoration

The visual concept milestone should start with typography:

- display/title roles
- operational heading roles
- compact panel heading roles
- field label roles
- value roles
- status/trust roles
- secondary diagnostic roles
- long text and missing-value behavior
- narrow-window wrapping rules

Only after text roles are legible should the milestone add surface treatment:

- panel depth
- luminous separators
- restrained glow
- angular or sci-fi framing
- orbital/radar motifs
- ambient background treatment, if useful

Decoration should support comprehension, not cover up weak information design.

## Concept Acceptance Checks

The milestone should be accepted only if the concepts:

- keep source/freshness/certainty visible
- preserve loading, empty, stale, failed, partial, gated, and missing-data language
- prove readable text containment in compact desktop windows
- avoid dashboard card soup
- avoid one-note cyan-on-black sci-fi styling
- keep diagnostics available but visually secondary
- show how the same grammar adapts differently for Lab, Sense, Atlas, and Core
- do not imply target-project adoption

## Do Not Do Next

Do not go straight to Atlas or Sense implementation.

Do not pick React, Tailwind, Shadcn, or another durable UI stack yet.

Do not define a durable bridge/data contract yet.

Do not promote the neutral M02 rigging pack into Aura Core yet.

Do not treat sci-fi surface treatment as a substitute for text hierarchy, state grammar, and trust language.
