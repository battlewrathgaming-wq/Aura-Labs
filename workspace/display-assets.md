# Display Asset Library

Status: Active Lab library map
Owner: Aura Lab Overseer

## Purpose

This page frames Lab's reusable presentation library as shelves of display craft.

Lab turns display pressure into reusable presentation assets. It does not own target source meaning, target adapters, target runtime behavior, or target adoption.

Core working line:

```txt
Targets translate themselves; Lab makes the window worth looking through.
```

## Shelves

### Display Materials

Folder:

```txt
workspace/display-materials/
```

Materials are reusable ingredients: small presentation treatments that can be composed into larger glass assets.

Examples:

- availability reason treatment
- warning / gap edge
- long text detail block
- freshness / basis rail
- progressive detail drawer
- compact value stack

Material pages should explain purpose, slots, states, visual structure, interaction/reveal, narrow behavior, verification minimum, and risks.

### Display Glass / Outputs

Folder:

```txt
workspace/display-outputs/
```

Glass assets are composed presentation surfaces made from accepted or understood materials.

They are target-trial candidates, not target adoption records.

Examples:

- Instrument Readout Panel
- future compact status band
- future source-first readout
- future comparison strip
- future activity/timeline surface

Glass pages should explain:

- purpose
- ingredients used
- slots and states
- reusable presentation value
- demo scaffolding to exclude
- target responsibilities
- trial readiness
- verification minimum
- risks / parked notes

## Catalog

Use:

```txt
workspace/display-schema-ledger.md
```

The ledger is the catalog/index only. It is not a backlog, source-project tracker, Dev runway, or target adoption record.

## Workflow

Recommended growth loop:

```txt
workshop idea
-> material requirement
-> material schema
-> prototype/reference
-> accepted material page
-> composed glass asset
-> target trial request
```

Target trial request means the target project asks which glass/features it wants to try, then maps itself.

## Target Selection Use

When a target project asks what it can use, point to:

- accepted display materials
- accepted display glass assets
- the current glass definition
- the handoff standard

The target should answer:

```txt
Which features do you want from this selection?
```

Lab should answer:

- what the asset does
- what files or reference pages embody it
- what is demo scaffolding
- what the target must provide
- what the asset must not imply

Lab should not answer:

- target source meaning
- target state mappings
- target adapter behavior
- target runtime ownership
- target adoption decision
