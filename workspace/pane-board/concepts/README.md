# Pane Board Concepts

Status: Lab sandpit spine
Context: Shape See / Pane Board concept notes

## Purpose

This folder holds non-authoritative concept notes for using Pane Board as a Human/agent spatial thinking surface.

These notes do not create implementation work, source-project adoption, bridge/runtime contracts, adapter work, generated UI, or product layout authority.

## Concept Loop

The current Shape See loop is:

1. Source project prepares meaning.
2. Source project assigns slim `#NN` handles to surface-facing parts.
3. Labs uses Pane Board to arrange those handles as spatial relationships.
4. Human reviews the shape, weight, order, and "almost" tensions.
5. Project UX reviews whether the sketch preserves source meaning.
6. Overseer decides whether anything becomes accepted evidence or a later runway.

## Working Rules

- Use source-owned artifacts for meaning.
- Use `#NN` handles for Pane Board mockups when source terms need protection.
- Treat board size as relational weight, not product dimensions.
- Treat board position as relationship, not final placement.
- Treat shadows as context, not focus.
- Keep diagnostics and mechanical details out of first-read sketches unless they are the thing being tested.
- Record why a shape was liked, adapted, parked, or rejected.

## Good First Test

For Sense Passive Telemetry:

1. Open the Sense meaning artifact with its slim surface reference index.
2. Put only `#NN` handles on the board.
3. Start with the first-read and activity texture handles.
4. Add boundary or shadow handles only if they prevent misread.
5. Judge whether the arrangement helps the Human understand how the pieces rest together.

The board is successful when it improves shared understanding without claiming product meaning or final layout authority.
