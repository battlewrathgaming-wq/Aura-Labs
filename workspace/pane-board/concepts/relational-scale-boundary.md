# Relational Scale Boundary

Status: Lab sandpit concept
Context: Pane Board / Shape See spatial mockups

## Statement

Pane Board maps display-form relationships for UX review. It does not define positional accuracy, production scale, or target component dimensions.

The board can show how parts rest together:

- what anchors the read
- what belongs near what
- what forms a cluster
- what qualifies a cluster
- what should be visually separated
- what acts as shadow context
- what belongs in detail or diagnostics
- what remains parked
- what should feel more prominent or quieter

The board does not define:

- exact x/y position
- exact pixel size
- final component dimensions
- production spacing
- typography scale
- responsive breakpoints
- target-project layout grid
- final target-project UI adoption

Size on the board means relational weight, not production dimensions.

Position on the board means relationship, not positional authority.

Spacing on the board means separation or adjacency, not final layout spacing.

Project UI/UX owns how these relationships become local product scale, density, components, and responsive behavior.

## Working Rule

Use Pane Board to map data forms and meaning relationships into a larger display story.

Do not use Pane Board as a source of positional accuracy.

When a sketch is reviewed, ask:

```txt
What relationship is this shape expressing?
```

before asking:

```txt
Where exactly should this go?
```

This keeps Pane Board useful as a shared Human/agent spatial language without turning it into product layout authority.
