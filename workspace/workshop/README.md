# Aura Lab Workshop

Status: Skunkworks and display-idea lane

## Purpose

This folder is for early display-element ideas before they become accepted Aura Lab milestones.

Use it for sketches, small proposals, interaction notes, material studies, and "could we display information like this?" thinking.

The workshop exists so Lab can explore taste and display mechanics without turning every idea into a Dev runway.

## Boundary

Workshop entries are not:

- product direction
- Dev runways
- accepted milestones
- bridge contracts
- target adapters
- Atlas, Sense, or Core doctrine
- shared Aura component claims
- hidden task queues

Ideas become executable only when Human / Overseer promotes them into `workspace/current.md`.

## Display Element Focus

Workshop ideas should be framed as display elements:

- what information the element helps display
- what slots it needs
- what state/freshness/basis/gap/warning pressure it handles
- how it behaves in narrow layouts
- what visual material or interaction hook it explores
- what must remain target-owned if another project later adapts it

Good workshop candidates:

- compact value rail
- source coverage chip
- warning edge / attention tooth
- readout detail reveal
- rolling counter / telemetry reel
- timeline bead strip
- state-change pulse
- compare strip
- stale/aged wash
- low-power diagnostics panel
- dense list compression
- long-basis containment
- status constellation / grouped pips

Avoid:

- full target-product skins
- target adapters
- domain labels copied from Atlas or Sense
- durable bridge contracts
- broad framework migration
- visual smoke systems as product direction

## Promotion Rule

To promote a workshop idea, Overseer should write or update `workspace/current.md` with:

- active milestone
- current executor
- source of intent
- expected handoff file
- ordered runway
- guardrails
- stop conditions
- required verification

Do not ask Dev to execute directly from this folder.
