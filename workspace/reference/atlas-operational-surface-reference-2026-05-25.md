## Purpose

Capture a Human-provided Atlas screenshot as a Lab reference for presentation structure, density, and transformation opportunities.

This note is not Atlas authority, not Lab product direction, and not a Dev task. It records portable display ideas that Lab may study while preserving Atlas-owned meaning.

## Current Read

The screenshot shows an Atlas surface with a left identity and navigation rail, a journey support panel, a central workflow area, gated action controls, and a detailed selection summary table.

The surface is already meaning-aware. It distinguishes queued discovery/provenance metadata from stored evidence and uses confirmation before an enrich action writes evidence.

The main presentation issue is not missing information. It is that many values carry similar visual weight, so the user has to read a long ledger before the current posture becomes obvious.

## Portable Ideas

- Left rail identity plus project posture.
- Journey support panel that explains next expected action.
- Confirmation-gated action strip for high-consequence transitions.
- Selection summary as a readout group rather than only a table.
- Boundary/effect language as a readout-basis/status treatment.
- Counts grouped into a compact instrument band.
- Zero-state counts shown calmly without implying failure.
- Detail ledger retained as secondary inspection, not first read.

## Narrow Layout Notes

The central ledger could become difficult in narrow shells. A stronger first-read pattern would keep the action posture, effect posture, and primary counters visible first, then move secondary rows into a reveal or stacked detail section.
