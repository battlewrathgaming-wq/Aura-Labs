## Accepted Model

Lab may develop reusable local utilities and shelf-stable outputs.

Once a version is useful enough to offer, it travels as a consumable version. The consuming project owns local use, generated outputs, review, acceptance, freshness, and retirement.

Working line:

```txt
A Lab utility travels as a consumable version, not as a continuing Lab-owned service.
```

## Examples

Presentation glass:

```txt
Lab provides the window.
The project owns what it shows.
```

Trace/source-map workbench:

```txt
Lab provides the lens.
The project owns the trace it produces.
```

## Trace Workbench Posture

Future trace/source-map tooling remains concept-only until a new packet opens it.

The useful shape is:

```txt
bounded source question
-> source-cited trace impression
-> durable project-local reference
-> owning project review
```

Trace for understanding. Cite source for trust. Return meaning to the owning project.

## Boundaries

This acceptance does not open implementation work.

It does not create:

- a Lab-owned source authority
- a continuing Lab service obligation
- target-project adoption
- source-project doctrine
- universal adapter behavior
- bridge/runtime contracts
- generated outputs as accepted truth

## Future Pickup

If Human chooses the tooling lane, the next clean step is a narrow concept/spec packet for a Trace Workbench or Source Map Workbench.

That future packet should define:

- bounded trace questions
- output artifact shape
- source citation expectations
- generated-output cleanup policy
- project-local ownership
- verification minimum
